识别工作台使用说明（OpenCV + OCR + PyTorch）
============================================

一、最简单的测试
----------------
1. 把完整的 1280x720 设计图截图放到：
   recognition_workbench\test_img
2. 双击本目录下的 RUN_RECOGNITION.bat。
3. 打开最新目录：
   recognition_workbench\test_out\run_时间戳\

如果只是给正式流程跑结构化结果，不想生成 annotated 预览图：
双击 RUN_RECOGNITION_NO_PREVIEW.bat。

二、PowerShell 指定目录
-----------------------
python recognition_workbench\run_recognition.py --input-dir "你的截图目录" --run-name "my_test"

长截图使用：
python recognition_workbench\run_recognition.py --input-dir "你的截图目录" --image-mode long_screenshot --run-name "my_long_test"

关闭预览图：
python recognition_workbench\run_recognition.py --input-dir "你的截图目录" --run-name "my_test" --no-preview

指定 NN 后端：
python recognition_workbench\run_recognition.py --nn-backend auto
python recognition_workbench\run_recognition.py --nn-backend onnx
python recognition_workbench\run_recognition.py --nn-backend pytorch
python recognition_workbench\run_recognition.py --nn-backend off

指定 ONNX FP16 模型：
python recognition_workbench\run_recognition.py --nn-backend onnx --onnx-model equipment_icon_resnet18_fp16.onnx

三、输出文件
------------
annotated\*_pipeline.png
  原图标注预览。绿色表示最终接受，红色表示需要复核，橙色表示半截卡片被拒绝。
  默认生成；加 --no-preview 或双击 RUN_RECOGNITION_NO_PREVIEW.bat 时不会生成。
icon_crops\*_cardXX_icon.png
  实际交给 OpenCV 和 PyTorch 的完整 icon 裁剪。
screenshot_pipeline_results.csv
  每张卡一行，包含 OpenCV、OCR、PyTorch top-k、最终名称和数量字段。
screenshot_pipeline_results.json
  同一轮的完整结构化结果。
screenshot_pipeline_summary.json
  本轮数量统计。它是流程统计，不是准确率证明。
recognition_model.json
  记录本轮使用的 PyTorch/ONNX 模型目录、实际 NN 后端和 equipment_name 标签契约。

四、识别顺序
------------
整图 -> 卡片/ROI 检测 -> 半截卡拒绝 -> OpenCV icon + OCR -> OpenCV 不确定时调用 ONNX/PyTorch。
只有 OpenCV 与名称 OCR/PyTorch 的证据满足阈值时才填写 final_equipment_name；冲突会保留 needs_review。
模型主要输出 equipment_name。equipment_id 只从当前 data\equipment_library.csv 动态映射，供兼容使用。

五、检查结果
------------
优先查看 CSV 的 final_status、final_equipment_name、recognition_source、opencv_confidence、
nn_equipment_name、nn_confidence、fragment_count、required_count 和 warnings。
partial_rejected 是预期行为：卡片边界或 icon 被截断时不识别，避免错误写入。

六、单独测试一个 icon
----------------------
该模式要求完整正方形 icon（至少 64x64），不能直接输入整张 1280x720 截图：
python nn_training_lab\pytorch_icon_training\scripts\predict_icon.py "icon.png" --model "nn_training_lab\pytorch_icon_training\models\run_20260722_181933" --top-k 5

这个命令在终端逐行输出 JSON 候选；它不会写正式 CSV 或用户数据。
当前 RUN_NN_INFERENCE.bat 是旧的 Paddle 单 icon 入口，验证 PyTorch 时使用上面的命令或本工作台。

七、ADB 分帧采集后识别
----------------------
如果 ADB 开发层已经生成：
workdir\automation\adb_capture_runs\run_xxx\manifest.json

设计图页推荐策略：
- 设计图页不要依赖“长截图后再切块”作为主流程。
- 先按稀有度逐步切换，每次切换后抓一张视口帧。
- OCR 只吃这些逐帧截图，并用 manifest 的 frame_index / scroll_index / next_resume_cursor 做去重和续跑。
- `viewport_full` 是设计图页这条链路的默认识别模式。
- `long_screenshot` 仅用于你手上已经有一张外部拼好的长图时做兼容测试，不是这条 ADB 流的主路。

最简单方式：
双击 recognition_workbench\RUN_ADB_MANIFEST_RECOGNITION.bat
然后把 manifest.json 完整路径粘进去。

命令方式：
python recognition_workbench\run_adb_design_fragment_recognition.py --manifest "workdir\automation\adb_capture_runs\run_xxx\manifest.json"

如果要直接调用 ADB 采集 8 帧后识别：
双击 recognition_workbench\RUN_ADB_CAPTURE_AND_RECOGNIZE.bat

或命令：
python recognition_workbench\run_adb_design_fragment_recognition.py --capture --frame-count 8 --overlap-ratio 0.35

输出目录：
recognition_workbench\adb_test_out\adb_design_时间戳\

额外输出：
adb_capture_context.json
  记录本轮使用的 ADB manifest、筛选出的 frame、原始滚动状态和识别 summary。

默认规则：
  is_duplicate_frame=true 的重复帧不会送入 OCR。
  success=false 或截图路径不存在的帧不会送入 OCR。
  如果确实要测试重复帧，可加 --include-duplicates。

八、验收注意
------------
请使用没有进入训练集的截图，并人工对照 annotated 预览和 CSV。当前数据长尾明显，流程成功数不能直接等于真实准确率，
没有独立真值标注前不得宣称达到 98%。

九、仓库页 -> 设计图页切换检查
--------------------------------
如果你现在已经停在“仓库”页面，只想先确认能不能切到“设计图”页，可以直接运行：

双击：
recognition_workbench\RUN_WAREHOUSE_DESIGN_TAB_CHECK.bat

命令：
python recognition_workbench\run_warehouse_design_tab_check.py

如果不想做截图确认，只想先看切页动作是否执行：
python recognition_workbench\run_warehouse_design_tab_check.py --no-confirm

输出说明：
  1. 会打印一份 JSON，里面有 navigation 和 warehouse_label_result。
  2. design_tab_confirmed=true 表示切页后已经确认是设计图页。
  3. 如果仓库标签识别依赖不可用，会保留切页动作结果，但会写 warning。
  4. 如果确认失败，会返回非 0 退出码，方便 bat 和后续脚本判断。

十、设计图页稀有度切换检查
--------------------------------
如果你已经停在“设计图”页，想先依次确认白/蓝/紫/金/彩几个稀有度切换动作是否能稳定执行，可以直接运行：

双击：
recognition_workbench\RUN_WAREHOUSE_DESIGN_RARITY_SWEEP.bat

命令：
python recognition_workbench\run_warehouse_design_rarity_sweep.py

常用参数：
python recognition_workbench\run_warehouse_design_rarity_sweep.py --resume-cursor 2
python recognition_workbench\run_warehouse_design_rarity_sweep.py --json-out "G:\ALLPeoject\PythonProject\AzurLaneResearchTracker-OCR\recognition_workbench\test_out\warehouse_design_rarity_sweep.json"

输出说明：
  1. 会生成独立的 run_<session_id> 目录，里面有 frames/manifest.json/actions.log/device_info.json/summary.json。
  2. summary.json 里的 next_resume_cursor 可以直接用于断点续跑。
  3. frames/ 里每张图对应一次稀有度切换后的截图证据。
  4. 如果某一步截图和上一帧完全一致，会在 warnings 里记录为疑似重复。
